## 故障现象

未登录状态下，标题画面（`https://h.nyaa.host:3096/`）点击屏幕**没有任何反应**，登录窗口（账号密码表单）不出现。

## 根因链（结论：macmini 数据库容器证书过期 → 前端认证配置拉取失败）

1. **前端资源域 5102 修复后，`/api` 域 3097 仍在使用过期证书**：`adventurertavern-db`（Node + 自建 HTTPS）挂载宿主 `AVG-AdventurerTavern/ssl/`，读其中的 `h.nyaa.host_bundle.crt`/`h.nyaa.host.key`（TrustAsia，**2026-08-31 04:59:59 GMT 过期**）。
2. 浏览器访问 `https://h.nyaa.host:3097/api/**` → `SEC_E_CERT_EXPIRED` → **所有后端请求被 TLS 层拒绝**（`database.apiBaseUrl = https://h.nyaa.host:3097/api`，见 `config.ts`）。
3. `TitleScreen` 加载时 `getAuthConfig()` 失败 → 返回 `null` → `authMode` 保持默认值 `'discord'`、`enablePasswordLogin=false`（后端实际是 `AUTH_MODE=password`）。
4. 点击屏幕 → `handleScreenClick()` 走 `authMode === 'discord'` 分支 → `handleDiscordLogin()` → `getDiscordAuthUrl()` 同样失败 → 只执行 `setAuthError(...)`，**`titleState` 仍停在 `'WAITING'`**；而 `authError` 只在 `AUTH` 态的弹窗里渲染 → **表现为「点击毫无反应」**。

> 即：证书过期是根因，前端错误分支缺少状态切换是「静默无反应」的直接原因。

## 追加修复：私有仓库清理逻辑的连坐删除 bug（2026-09-12 当日发现）

**事故**：按新 sha 重建 db 镜像时，`database-server/rebuild.py` 的 "keep-only-latest" 清理把注册表里 **`adv-tavern-db` 的所有 tag 删光了**（`/v2/adv-tavern-db/tags/list` → `"tags": null`）——macmini 下一次 `docker compose pull` 会失败。

**根因**：
1. Docker Registry 只接受**按 digest** 删除（实测按 tag `DELETE /v2/<repo>/manifests/<tag>` 返回 `400 DIGEST_INVALID`）；
2. 镜像**内容完全相同**的重建（本次只改了 git sha，未改任何代码）会让新旧 tag **指向同一个 manifest digest**；
3. 旧清理逻辑"列出过期 tag → 取其 digest → 删除 digest"，删掉的正是 `latest`/新 sha tag 也在引用的那个 manifest → 所有 tag 一起消失。

**修复**（三个 `rebuild.py` 均已加固）：删除前先解析**保留 tag**（当前 sha + `latest`）的 digest，凡与保留 tag 共用 digest 的过期 tag **直接 SKIP** 并打印原因；同时把 SKIP 文案改成英文以适配 Windows 控制台编码。
- `rebuild.py`（前端）、`database-server/rebuild.py`、`file-server/rebuild.py`
- 验证：用共享同一 digest 的临时 tag 跑一次 `registry_cleanup(keep={475e59b, latest})` → 输出 `SKIP zzztest: shares manifest e7e9636eeb7a... with a kept tag`，三个 tag 全部保留（改前会全部消失）；随后清掉测试 tag 并重推真实 tag。

> ⚠️ **跨项目同类隐患（未修，仅记录）**：工作空间里 `MyToken`（`keep_digests`）、`NyaaChat`、`NyaaCLI`、`NyaaLibrary-MCP` 已有同类保护，但
> **`Caddy`、`CLIProxyAPI-deploy`、`AIStudioToAPI-deploy`、`Keeper_CoC-TRPG`、`NyaaDIYPC-MCP`、`NyaaAcount`、`NyaaChat-Docs`、`NyaaChat-MCP`、`NyaaQiny-MCP`** 的 `registry_cleanup` 仍是"按 digest 直接删"，在**内容未变的重复构建**下会同样删光仓库 tag。建议后续按 AVG 的写法统一加固（详见 `~/.dsh/AGENTS.md` 的私有仓库备忘节）。
